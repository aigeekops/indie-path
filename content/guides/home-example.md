# 把一个想法，推进到真实反馈。

示例：把工作记录整理成客户报告。下面的记录、报告与判断均为教学模拟，不是真实用户或经营证据。

## 找到具体问题

> 示例访谈：“每次交报告，我都要从聊天和表格里重新找记录。”

| 分清什么 | 在这个示例中怎么记 |
| --- | --- |
| 用户表述 | 需要在多个地方查找记录；还要查看一次实际过程。 |
| 问题假设 | 统一整理记录，可能减少报告准备工作。 |
| 尚未确认 | 多久发生一次？现有办法哪里不够用？谁愿意付费？ |

**下一次确认：** 请对方带一份旧报告，回顾最近一次交付。

## 做出最小流程

1. **输入工作记录**\
   先支持粘贴文本，保留日期和来源。
2. **整理成报告草稿**\
   按项目归类；不确定的内容标为待确认。
3. **人工核对后导出**\
   用户检查事实，再复制或下载报告。

**首版保留：** 输入、预览、修正、导出。  
**暂不做：** 团队空间、多套主题、自动发送。

## 交给用户试用

### 客户报告 / 草稿示例

| 来源记录 | 整理后的报告条目 |
| --- | --- |
| 周二：完成页面初稿 | 已完成：页面初稿，等待客户确认。 |
| 周三：客户尚未回复 | 待处理：收集页面修改意见。 |

**交给用户检查：** 事实是否准确？是否遗漏事项？导出结果能否用于交付？

**试用记录留空待填：** 是否独立完成、卡在哪一步、是否实际采用。演示数据不计入个人成果。

## 根据反馈决定

| 选择 | 需要什么依据 | 下一步行动 |
| --- | --- | --- |
| 继续 | 用户实际采用，仍有明确需求 | 完成下一项最小验证。 |
| 调整 | 具体卡点阻碍了结果 | 修正一个问题后再试。 |
| 等待 | 还没到使用周期，反馈不足 | 约定回访时间，不扩大开发。 |
| 停止 | 需求不成立，或投入难以持续 | 留下原因，停止本轮投入。 |

**分别记账：** 能力成果、真实使用、付费与成本。任一项未知，都不补造成“成功”。
