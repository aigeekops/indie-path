# 上线一个别人能用的版本

## 为什么做

代码生成后，环境、配置和维护仍是交付的一部分。本指南保持静态；你学习构建的业务产品是否需服务端，按实际功能决定。

## 开始条件

核心流程和必要检查已通过；明确交付物。

## 学习要点

- 配置与环境
- 静态/服务端部署
- 版本与恢复

## 成果模板

```text
版本/地址：
构建与启动命令：
配置来源：
持久化位置：
检查结果：
恢复步骤/已验证边界：
```

## 教学示例

教学示例：GitHub Pages 支持本学习站的静态模块与 hash 路由，不是商业交易或SaaS的免费托管；也不会运行 Python API；需要持久化的业务数据须另选适合的实现。

## 常见问题

- 线上白屏：检查子路径、资源请求与控制台。
- 以为恢复代码就恢复数据：分别演练并记录。

## 交付成果

- 发布版本
- 运行与配置说明
- 备份恢复结果

## 下一步

展示真实演示，进入用户接触和交易验证。

## 完成标准

- 另一位用户可以访问并完成任务
- 版本与配置可确认
- 恢复步骤经过测试环境验证

## AI参与方式

辅助配置与排障，不把“命令成功”当实际验收。

## 行动步骤

### 选择与功能相符的托管

本学习站与符合规则的教学演示可用 GitHub Pages；商业交易或SaaS不能把免费Pages当业务托管。静态业务产品也要核对用途条款；业务若需服务端或数据库，选择支持该能力的环境。不要把学习站接入后端。

#### 这一步留下

托管选择与理由。

### 从干净环境构建

按项目说明安装运行，记录版本、必需配置与持久化位置。配置不写入公开文件。

#### 这一步留下

可复现运行说明。

### 部署并验证真实操作

确认域名、HTTPS、资源路径、线上版本、核心输入输出与日志。已有部署沿用原平台。

#### 这一步留下

可访问版本和检查结果。

### 做一次恢复练习

在测试环境恢复前一版本，并还原一份样例备份。涉及数据结构改变要单独验证，不能只回退代码。

#### 这一步留下

恢复记录与限制。

### 让别人接手

请同事按文档运行或检查服务，记录仍需口头补充的地方并修正。

#### 这一步留下

接手反馈。
