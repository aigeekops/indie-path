# 完成一次小程序、调试与变式

## 为什么做

AI 能补充代码，但你必须有阅读、试验和纠错能力，才不被一次次整段重写困住。

## 开始条件

完成最小页面，了解输入与输出。

## 学习要点

- 变量与集合
- 函数与判断
- 调试与小步变更

## 成果模板

```text
运行命令/代码位置：
输入场景（正常/空列表/缺字段） | 预期输出 | 实际输出
发生错误的位置/如何定位：
修改原因：
Git 变更位置/提交记录：
独立变式条件：
新条件下的预期/实际结果：
```

## 教学示例

教学示例：三条记录中两条属于项目 A，筛选后应为两条；“结果看起来合理”不如直接检查数量与标识。

## 常见问题

- 复制后不知道运行哪里：回到课程最小运行示例。
- 改了很多文件才检查：缩小为一个函数、一个变化。

## 交付成果

- 筛选函数与样例
- 一次调试记录
- 独立变式结果

## 下一步

通过后可开始最小服务端与界面，不要求先学完整计算机课程。

## 完成标准

- 筛选函数在正常、空与缺字段场景表现明确
- 能定位并修复一个已知错误
- 不依赖原对话完成变式

## AI参与方式

使用 Cursor 或 Claude Code 辅助整理与局部实现，自己核对关键事实和结果。

## 行动步骤

### 处理三条样例记录

先从 [Node 官方下载页](https://nodejs.org/en/download) 选择适合系统的 LTS 安装方式。打开终端或 PowerShell，进入自己的练习目录，用 node --version 确认；新建 records.js，填入本页最小输入，追加 console.log 后用 node records.js 运行。先看数组、对象、函数，再按 filter 示例写按项目筛选的函数；日期筛选放到第三步增加，空输入返回约定结果。

#### 这一步留下

可运行的小函数。

### 先预测再运行

预测三个输入的输出：正常、空列表、缺字段。运行并核对，不把模型解释当执行结果。

#### 这一步留下

预测与实际对照。

### 只委托一个小变化

让 Cursor 或 Claude Code 增加日期筛选。先按 Pro Git 初始化练习仓库，用 git status 与 git diff 核对变化，只暂存本练习文件并提交。再逐行解释 AI 修改，运行既有样例，并单独提交这次变化；不熟悉提交身份设置时先完成书中 First-Time Git Setup。

#### 这一步留下

一个可审查变更。

### 独立修一次错误

在练习副本改错字段名，读报错和变量值，定位后修复。最后不依赖原对话换一种筛选条件。

#### 这一步留下

故障与变式练习。
