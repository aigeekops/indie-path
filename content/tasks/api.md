# 打通接口与数据存储

## 为什么做

AI 可以写接口，但数据是否保存、错误如何返回，需要你用实际请求验证。先做最小读写，再扩大功能。

## 开始条件

已经写出输入输出约定；没有开发经验者先完成基础桥接。

## 学习要点

- 输入校验
- 数据持久化
- 请求与错误调查

## 成果模板

```text
技术路径/运行命令/代码入口：
接口 | 输入与约束 | 正常/失败/空结果预期 | 实际响应/证据位置
数据位置/环境配置来源（不填密钥）：
重启前后的记录标识/读取结果：
缺字段/未知标识/重复提交的结果：
路由→校验→处理→存储的代码位置：
独立增加的字段/修改与验证结果：
仍未验证：
```

## 教学示例

教学示例：POST 创建 record-01，GET 能读取它，服务重启后仍可读取；这比仅返回固定 JSON 多验证了存储。

## 常见问题

- 数据重启丢失：确认使用真实存储而非内存列表。
- 前端失败就改 CORS：先查真实请求、URL和响应，再判断原因。

## 交付成果

- 可复现请求集合
- 测试数据与重启验证
- 运行和配置说明

## 下一步

接入界面与身份授权；关键行为进入验收任务。

## 完成标准

- 请求经过真实服务端和存储
- 错误能定位，敏感配置未写入代码
- 能够解释输入到输出的链路

## AI参与方式

用已有技术栈，小步委托、运行验证。

## 行动步骤

### 只选一条技术路径

已有 Python 读 FastAPI 三份材料；已有其他后端保留原栈；没有基础可用课程 Node/Express 路线。不要同时修两套。

#### 这一步留下

一个服务端项目与运行说明。

### 实现一次创建和读取

只保存工作记录的必要字段。先以 API 客户端或框架文档界面调用，不依赖前端完成。

#### 这一步留下

创建和读取请求及响应。

### 接真实存储

在测试库保存记录，重启后重新读取。配置通过环境传入，不把生产数据用于练习。

#### 这一步留下

持久化结果。

### 跑边界样例

检查缺字段、未知标识与重复提交的约定行为。请求失败保留状态与错误，不假装成功。

#### 这一步留下

边界结果表。

### 解释并改一个条件

说明路由、校验、处理、存储的位置，再自己增加一个允许的字段。

#### 这一步留下

可解释的调用链与小修改。
