# 用自媒体内容带来第一批实际用户

## 为什么做

围绕真实问题展示解决过程，让读者能亲自使用产品。每轮只选一个主渠道、一项承诺和一个可检查的行动；微信、小红书、X、YouTube按受众选择，不要求同时经营四个账号。

## 开始条件

已有目标用户原话、诚实演示和可用体验或预约入口；先用[首批用户接触](#/task/reach)确认用户在哪里。素材可用明确标注的教学模拟，发布和经营结果按真实发生记录。应用或小程序可承接个人路线对应的获客任务。

## 学习要点

- 用户问题与选题
- 平台内容制作与单一体验入口
- 内容编号到使用、付款的关联

## AI提示词包

```text
第一轮 · 只做选题收敛
这是我的用户原话与三条讨论（粘贴）。请从里面选出一个最具体的问题，并说明哪条讨论证明有人在问。
硬约束：不要编造讨论或用户；不要给一堆选题，只给一个。

第二轮 · 生成平台化骨架
主渠道是 ______，问题与结果是 ______。请按该平台的常见结构给一个内容骨架（标题/开头/步骤/限制/入口）。
硬约束：不得添加客户评价或效果数字；模拟素材必须标注。

第三轮 · 检查承诺与限制
这是我的成稿（粘贴）。请逐句标出：可兑现 / 夸大 / 无证据，并给删除建议。
硬约束：只删不增；不得替我写"提升 300%"这类数字。

第四轮 · 整理反馈到下一组
这是发布后的真实回复（粘贴）。请归为：理解问题、使用阻塞、付费咨询；并给 C02/C03 各一个选题。
硬约束：不得编造评论；没有回复就写"无回复"。
```

## 成品样例

一份合格的成果长这样（示例数据，只用于对照格式）：

- 主渠道：微信公众号；理由：目标用户在职场上用微信，且账号已有读者；暂不选小红书（账号未起步）
- 问题原话："数据要从小红书和生意参谋分别导"（10-20 录音）；三条讨论来自两个社群（10-21）
- C01：标题《给客户写进度报告，先把这 3 类记录分开》；开头给结果样张；3 步配图；结尾写"我是开发者，当前只支持两种后台"
- 成功事件：读者打开样例页并实际导出一份
- 台账：C01 已发布（10-26，链接）；C02 计划"字段对不齐怎么检查"；C03 计划"导出前看这两处"
- 发布前：素材已获许可；模拟数据标注；手机预览通过

同样的工作量，但这些**不能用**：

- 四个平台同时发——没有一个是按受众选的
- 只有点赞或咨询就算有效——没有追到使用
- 没有账号就把草稿标成"已发布"

## AI边界

- 可以让 AI 做：收敛选题、生成平台化骨架、检查承诺与限制、把回复归类成下一组选题
- 不能让 AI 做：编造用户原话或评论、生成虚假案例、替你决定主渠道
- 必须你本人判断：问题是否来自真实讨论；内容里的功能是否真能兑现；发布与商业声明是否合规

## 行动步骤

### 选一个主渠道和真实问题

保存一条用户原话与3条相关讨论的脱敏出处，检查谁在问、已有做法和使用意图。先选一个主渠道，写为何选它及暂不选其他渠道的理由；已有账号也要检查读者是否匹配。

先读HubSpot的内容创作框架、推广与效果分析选段，不要求读完整课程。公众号可试完整教程，小红书可试场景图文，X可试目标语言讨论，YouTube可试完整演示；这些是候选表达方式，不是人群或流量保证。

#### 这一步留下

主渠道、真实问题、讨论出处、账号条件与待验证假设。

### 按平台做出第一份内容

只读所选平台的资料，按下面的顺序做一份内容：

**微信公众号**  
先学：[腾讯客服](https://kf.qq.com/product/weixinmp.html)检索图文编辑、预览、发布、内容分析；在[公众号后台](https://mp.weixin.qq.com/)核对权限。  
依次做：用户问题作标题 → 开头展示结果 → 3步操作配图 → 说明限制与作者身份 → 设置一个可用体验或咨询入口 → 手机预览。

**小红书**  
先学：[创作平台](https://creator.xiaohongshu.com/)、[标题封面选读](https://school.xiaohongshu.com/lesson/normal/af0fe7e97bb0433fac9da5d1df52b07f?viewSource=LESSON)与[规则中心](https://school.xiaohongshu.com/rule)，完整动态正文需登录核对。  
依次做：真实结果作封面 → 4张图依次展示问题、输入、操作、结果与限制 → 简短正文 → 核对商业声明和允许的下一步。

**X**  
先学：[官方入门](https://business.x.com/en/basics/get-your-business-started-with-x)的 Creating your profile → Posting → Engaging。  
依次做：资料页写适合谁与作者身份 → 用目标语言写问题和结果 → 加可复现的短演示 → 一个体验入口 → 回应相关讨论。

**YouTube**  
先学：[桌面上传](https://support.google.com/youtube/answer/57407?hl=zh-Hans&co=GENIE.Platform%3DDesktop)的详细信息、检查、公开范围及[链接概览](https://support.google.com/youtube/answer/13748639?hl=zh-Hans)。  
依次做：脚本 → 先展示结果再完整演示 → 标题、缩略图、字幕或旁白 → 说明限制与下一步 → 私享预览后公开。

图数和长度是本站练习安排，不是算法要求。小红书不默认允许外链、二维码或站外私聊，按本账号规则选择动作。YouTube Shorts说明和评论中的网址不可点击；长视频可点击外链需要高级功能，按官方条件检查频道资料链接等入口，不能只贴网址就认为能跳转。

客户素材取得许可才公开，模拟示例明确标注；发布前从观众视角核对产品确实能兑现演示。

#### 这一步留下

完整成稿或视频、素材依据、规则核对与观众视角预览记录。

### 把内容接到一次产品行动

将首篇标为C01，后两条计划为C02、C03，分别回答一个问题、展示一段过程、解决一个阻塞。每条只设一个行动，先定义成功事件，例如“导出并实际用于客户沟通的报告”；注册和打开页面另记。

链接被允许时，可在产品地址加来源参数，例如 https://example.com/?utm_source=x&utm_medium=organic_social&utm_campaign=first_users&utm_content=C01 。这是格式示例，先替换成真实产品并验证。参数只标来源，不会自动统计使用或识别跨设备的同一个人。

用产品已有统计或经同意的人工台账，关联内容编号、匿名用户代号、成功事件与订单索引。私信咨询、品牌搜索等来源若靠用户自述就标“自述”；无法确认则标未知，不把咨询人数填成试用人数。

#### 这一步留下

C01—C03排期、成功事件、来源识别方式与一次入口走查。

### 发布并处理真实反馈

按规则发布首篇，记日期、链接和版本；未发布保留待发布与原因。自己走通内容到产品的过程，排除测试访问；回复具体问题，经对方同意再邀请试用或回访。内容里的自家产品、赠送和付费合作如实说明，不能伪装普通用户背书。

将真实回复送入C02/C03选题。AI可辅助提纲、翻译和字幕，事实、语言与承诺由作者核对。没有账号或发布条件时可练成稿，不能将草稿标成已发布。

#### 这一步留下

发布记录、问题与答复、排除测试后的原始数量及待办。

### 交接到使用和付费复盘

为C01设截止日与后续使用窗口，分开记平台曝光/阅读、产品访问、开始、首次成功、付款和退款。真实为零才写0，取不到记未知；没有开放支付就写未开放，不用意向购买代替付款。

带着同一内容编号进入[内容获客复盘](#/task/content-review)，继续查再次使用、付费和投入。网页产品收费问题接[收费交付](#/task/charge)，应用或小程序接个人路线对应的变现任务。没人开始先查人群和入口，有人开始但没完成先查产品阻塞。

#### 这一步留下

内容台账、实际行为与未知项，以及下次观察节点。

## 教学示例

以下都是本站编写的教学模拟文案，没有真实发布、客户或收入结果。发布前替换入口，核实功能与限制，不复制不存在的能力。

**微信成稿骨架**  
标题：《给客户写进度报告，先把这3类记录分开》  
开头：“本例用模拟记录，演示如何区分已完成、待确认和阻塞。”正文依次放原记录、项目与日期校验、预览与导出三步配图。结尾：“我是这个工具的开发者。当前版本本地处理，不支持团队同步；请通过本文可用的体验入口试一份示例，告诉我卡在哪一步。”

**小红书4图脚本**  
封面：“客户周报，总在重抄？”；图2：“分清项目与日期”（模拟输入）；图3：“预览，检查漏项”（过程）；图4：“导出前确认这两处”（结果与限制）。正文：“我是开发者，这组模拟数据演示从CSV到报告，复杂排版仍需人工检查。你最容易卡在哪一步？”下一步按账号允许方式设置，不照抄站外引流口令。

**X英文帖草稿**  
“Still rewriting client updates from scattered notes? I’m building a CSV-to-report tool. This demo uses sample data: choose a client → review entries → export a PDF. Files stay in your browser; team sync isn’t supported yet. Try the sample: [your working link]. Which step blocks you?”配真实操作短演示，功能描述须与实现一致。

**YouTube脚本**  
标题：“Turn work logs into a client update — CSV to PDF”。0:00结果与适合谁；0:15模拟输入；0:30导入、筛选和预览；1:30空数据或字段错误；2:00导出与人工检查；2:30下一步及价格/试用限制。时间只是录制提纲，不承诺操作耗时。说明补样例、操作章节、限制及验证过的体验入口；Shorts另核链接位置。

## 常见问题

- 多平台复制却无人使用：先选一个验证，再按有效问题改编。
- 只有点赞或咨询：继续追使用，缺数据明确记录。
- 没有完整分析后台：用可见指标与匿名台账，未知保留，不为练习购买会员。

## 交付成果

- 一个主渠道的依据、三条选题及至少一份已发布内容
- 体验入口、匿名来源台账与使用付费观察节点

## 完成标准

- 受众问题有出处，主渠道及选择理由明确
- 至少一份内容已发布，素材与限制真实，体验入口已实际检查
- 内容编号能关联使用记录或明确的归因缺口，测试数据已排除
- 实际使用、付款、退款与未知分开记录，已写下一次观察节点

## AI参与方式

辅助提纲、字幕、翻译和反馈归类，不生成虚假评价或编造用户数据；发布、互动与商业承诺由作者核对。
