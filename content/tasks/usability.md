# 观察用户独立完成核心任务

## 为什么做

功能能运行不等于用户能完成。AI 可以润色界面，真实操作才会暴露理解与流程问题。

## 开始条件

已有主流程，能找到目标用户。

## 学习要点

- 任务设计
- 不引导的观察
- 核心完成行为

## 成果模板

```text
任务/成功行为：
用户日常环境/交付格式：
用户是否完成：
哪里停住：
我提供的帮助：
输出实际用于哪里：
修订后结果：
```

## 教学示例

教学示例：用户在你指导下导出应记“有帮助完成”；自己找到导出并用于交付才支持“独立完成”。

## 常见问题

- 一直教用户点击：暂停指导，记录实际卡点。
- 样本小却宣称所有人都能用：只报告本轮观察。

## 交付成果

- 试用记录
- 优先问题
- 修订结果

## 下一步

严重阻塞修复后再发布；完成只是技术与使用证据。

## 完成标准

- 任务描述没有逐步点击提示
- 是否提供帮助有记录
- 至少一次修订经过重新观察

## AI参与方式

使用 Cursor 或 Claude Code 辅助整理与局部实现，自己核对关键事实和结果。

## 行动步骤

### 写一个真实任务

给出目的和材料，如“把这份记录生成可交付报告”，不写“点击右上角”。

#### 这一步留下

任务与成功定义。

### 观察并记录

可先约三位目标用户，这是发现问题的起步练习。请其说出想法，先观察，必要帮助要单独记录。

#### 这一步留下

逐次操作与帮助记录。

### 按影响排序

阻塞完成优先于误解和装饰；分清个人偏好与重复发生的障碍。

#### 这一步留下

问题优先级。

### 修一轮再观察

只修主要障碍，再让用户或新用户完成相同目的。测试陌生输入，不只用演示数据。

#### 这一步留下

修订前后对照。
