# 观察用户独立完成核心任务

## 为什么做

功能能运行不等于用户能完成。AI 可以润色界面，真实操作才会暴露理解与流程问题。

## 开始条件

已有主流程，能找到目标用户。

## 学习要点

- 任务设计：给用户的应是"目的 + 材料"（例如"把这份记录整理成可交付的报告"），而不是"点右上角、选导出"。用户带着自己的目标来，不是照剧本走；你把步骤写死，测到的只是"他听不听话"。
- 不引导的观察：先观察再出手。一旦你开口指路，你观察到的就是"在你指导下能做"，不是"自己能做"。帮助要单独、事后记录，不能混进任务说明。
- 核心完成行为：先定义什么叫"完成"。是导出了文件，还是文件真的被拿去用了？只有后者才算用户独立完成了核心任务——前者只是界面能跑通。

## 成果模板

```text
任务说明原文（不得含"点击/打开"等步骤词）：
成功行为（做到什么算完成，例如文件被发给客户）：
用户 | 日常环境/设备 | 是否完成 | 在哪一步停住（原话） | 我提供的帮助（具体）
完成用的是演示数据还是用户自己的材料：
产出物去向（发给了谁/用在哪）：
本轮只改了哪一处 → 新用户复测结果：
仍未解决 / 只在这一轮观察到的：
```

## 教学示例

教学示例：用户做到一半问"导出的按钮在哪"，你指了一下——这一次要记"提供了帮助：指出导出入口"，不能算独立完成。另一轮，用户自己找到了导出，并把生成的报告发给了客户当作交付物——这才是"独立完成核心任务"。区别在于"界面能不能跑通"和"用户能不能达成自己的目的"是两件事，可用性观察只认后者。

## 常见问题

- 一直教用户点击：发现自己在逐句指导时立刻停。你每指一次路，测到的就少一分"独立"。把卡点记下来，事后统一改界面，而不是当场救火。
- 样本小却宣称"所有人都能用"：只报告本轮观察到了几个人、各自卡在哪。三个人的结果不是统计结论，是"这一版至少有这几个坑"。
- 把"用户卡住"当成用户笨：卡住几乎都是界面没把下一步交代清楚。记录"他在哪一步停住、当时在找什么"，这是改产品的线索，不是评价用户。

## 交付成果

- 试用记录
- 优先问题
- 修订结果

## 下一步

严重阻塞修复后再发布；完成只是技术与使用证据。

## 完成标准

- 交给用户的任务说明里没有"逐步点击"式的提示（如"点击 X""打开 Y"），只有目的与材料。
- 每次观察都记录了"是否提供了帮助、具体帮了什么"，且至少一次是零帮助下完成。
- 至少一次修订后，用同一目的让（新）用户重新做，并记录了修订前后的对照。

## AI参与方式

- 可交给 AI：把观察记录整理成问题清单、生成修订后的界面文案、把卡点归类。
- 必须自己核验：任务说明里没有逐步提示；帮助记录是事后补的而不是混进任务；复测用的是新用户或新输入。
- 不能交给 AI：判断"用户是否独立完成"以及"哪个卡点是主要障碍"——这必须基于你亲眼观察到的行为。

## 可运行起点

```text
一、约人（先约 3 位，不追求样本量）
对象：最近真的做过这件事的人（不是来捧场的同事）
时长：20 分钟，线上或当面
开场白（照念）：
"我在看这个工具好不好用，不是考你。请你按自己的习惯做，我不会教你；卡住也正常，那说明我们要改。"

二、任务卡（只给目的与材料，不写点哪里）

材料：records.csv（或你的真实样例）

三、观察记录表（每次一份）
用户 / 日期 / 设备：
开始时间 / 结束时间：
他在哪一步停住（原话）：

...

五、照着填（这是本任务的成果）
```

## AI提示词包

```text
第一轮 · 把任务说明改成"只有目的与材料"
这是我写的任务说明（粘贴）。请删掉所有"点击/打开/进入/选择"这类步骤词，只保留目的与材料。
硬约束：不要替我编造材料；改写后逐句说明删了什么、为什么。

第二轮 · 把观察记录整理成问题清单
这是我的观察记录（粘贴）。请分成三类：阻塞完成、理解误解、个人偏好。
硬约束：每条都必须引用原话；没有原话支撑的，标为"待补证"。

第三轮 · 只改一个主要障碍
根据问题清单，指出风险最高的一个障碍，并给一个最小修改（文案或布局），说明它针对哪条原话。
硬约束：一次只改一处；不要顺手改视觉风格。

第四轮 · 设计复测
我改了这一处（粘贴改动）。请给我一个复测方案：找谁、给什么任务、记录什么、什么算通过。
硬约束：复测要用没见过的输入；不得把"我解释后他能做"算作通过。
```

## 成品样例

一份合格的成果长这样（示例数据，只用于对照格式）：

- 任务说明原文（无逐步提示）："把这份原始记录整理成一份能直接发给客户的周报。"
- 成功行为：用户产出的文件被真的发给了客户
- 用户 A / 笔记本 / 未完成 / 停在"不知道导出在哪" / 我指了右上角（有帮助）
- 用户 B / 手机 / 完成 / 未停住 / 无帮助 / 文件发给了客户
- 用户 C / 笔记本 / 完成 / 停在"周报格式不确定" / 我说明了一次格式（有帮助）
- 产出物去向：B 发给了客户；C 带回去改
- 本轮只改一处：把"导出"按钮从图标改成"导出周报"文字 → 新用户 D 零帮助完成
- 仍未解决：手机上表格显示不全（只观察到 1 例）

同样的工作量，但这些**不能用**：

- 任务说明写"点击右上角导出"——测到的是听不听话，不是能不能用
- 把"我教了他三遍，他做完了"记成独立完成
- 用三个同事的结果宣称"所有用户都能用"

## AI边界

- 可以让 AI 做：把任务说明删成"目的 + 材料"、把观察记录归类、生成修订文案、设计复测方案
- 不能让 AI 做：替你判断"用户是否独立完成"、替你编造用户原话、把"你解释后他能做"算成通过
- 必须你本人判断：帮助是否发生在关键步骤；卡点是界面问题还是任务本身太难；复测是否用了新用户或新输入

## 行动步骤

### 写一个真实任务

写出一个只有"目的 + 材料"、没有"点哪里"的任务说明，例如"用你手上的这份原始记录，产出一份能直接发给客户的周报"。同时写明成功行为：用户产出的文件是否真的被拿去发了客户。写完对照检查——如果说明里出现了"点击""打开""进入"这类词，就还在写剧本，需要重写。

#### 这一步留下

任务说明与成功定义（无逐步提示）。

### 观察并记录

可先约三位目标用户，这是发现问题的起步练习。请其边操作边说出想法；用户沉默超过十秒你再问"你现在在找什么"，不要直接指路。必要帮助单独记录，并注明发生在哪一步、帮了什么。

#### 这一步留下

逐次操作与帮助记录（时间点 + 原话 + 帮助）。

### 按影响排序

阻塞完成优先于误解和装饰；分清个人偏好与重复发生的障碍。

#### 这一步留下

问题优先级。

### 修一轮再观察

只修主要障碍，一次只改一处。再让用户或新用户完成相同目的，并换用没见过的输入（不是演示数据）。记录修订前后是否还卡在同一个地方；仍卡住就说明改错了方向。

#### 这一步留下

修订前后对照（含换输入后的结果）。
