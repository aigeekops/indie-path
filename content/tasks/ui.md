# 完成一个可以操作的界面

## 为什么做

界面生成很快，但用户是否看懂输入、状态与结果，仍需要观察。先连接真实流程，再优化视觉。

## 开始条件

已确定流程与接口约定；服务端可先独立验证。

## 学习要点

- 组件与状态
- 表单校验
- 异步和错误反馈

## 成果模板

```text
页面/主动作/组件位置：
输入字段/校验/输入保留：
写入请求→读取请求/实际响应证据：
正常/加载/空结果/失败各自的表现：
刷新与重复点击的行为：
输出格式/导出或打印预览检查：
试用日期/任务/是否提供帮助：
实际使用问题：
本轮修改/再次观察或待核对：
```

## 教学示例

教学示例：生成失败后保留已输入记录并显示可理解原因；一个看起来漂亮但没有接上导出的按钮不能算完成。

## 常见问题

- 只能展示成功：逐一构造慢请求、空列表与失败。
- 直接生成整站后不会改：回到一页一条流程。

## 交付成果

- 真实流程界面
- 四状态结果
- 用户观察记录

## 下一步

继续双账号权限与可用性检查；已有界面可用成果确认。

## 完成标准

- 界面连接真实数据
- 刷新与失败行为符合约定
- 能解释主要状态变化

## AI参与方式

委托局部实现，逐步查看差异，避免一次生成整站。

## 行动步骤

### 复用熟悉的界面技术

未独立做过界面时，先按 HTML/CSS 示例做最小页面，再用 JavaScript 的数组、对象、函数和 filter 写一个筛选。能解释后再按 React 示例建立组件；已有 Vue 等界面经验直接做同等行为，不更换整套技术。

#### 这一步留下

最小界面入口。

### 做输入与预览

先用教学样例完成表单和预览，明确标记样例。增加必填校验，保留用户输入。

#### 这一步留下

可操作表单。

### 连接真实接口

读取接口约定，先用写入请求保存，再用读取请求刷新预览。最后把预览内容导出为一种固定格式（例如文本文件）；先使用打印页面另存 PDF 或浏览器已有下载能力，不引入复杂文档格式。检查请求与响应，不用假数据遮住失败。

#### 这一步留下

真实主流程。

### 补四种状态

正常、加载、空结果和失败；重复点击时按约定处理，错误后能继续操作。

#### 这一步留下

状态检查表。

### 请用户试做

给目标，不逐步指导。记录理解错、重复操作和输出问题，修改首要卡点。

#### 这一步留下

一次试用修订。
