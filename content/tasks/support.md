# 建立支持入口，处理一次反馈

## 为什么做

一个人可以借助 AI 处理更多事务，但服务承诺、故障责任和客户关系需要自己把握。先让问题可追踪，再自动化重复劳动。

## 开始条件

已有试用或交付，需要响应反馈。

## 学习要点

- 支持入口
- 优先级与承诺
- 故障复盘

## 成果模板

```text
支持入口/可履行的响应安排：
用户任务/现象/真实事件或演练：
影响与必要证据：
已承诺内容：
处理状态/优先级：
事实时间线：
原因证据：
防复发动作/帮助条目位置：
本次支持时间：
```

## 教学示例

教学示例：客户导出失败，先确认范围、保留订单与输入，再定位；不能先由 AI 回复“已修复”却没有运行验证。

## 常见问题

- 每次重复解释：先改引导或帮助，再考虑自动回复。
- 客服让收入看起来很好：记录每单支持时间。

## 交付成果

- 支持入口
- 台账
- 一次复盘或明确尚未发生故障

## 下一步

进入经营核算；没有真实故障可做演练，但与真实反馈分开。

## 完成标准

- 支持范围与入口明确
- 问题状态与人工时间可追踪
- 复盘或演练与实际事件区分

## AI参与方式

使用 Cursor 或 Claude Code 辅助整理与局部实现，自己核对关键事实和结果。

## 可运行起点

```text
一、写清支持入口与可履行的响应安排
入口：______（邮箱 / 表单 / 群）
响应安排：______（例：工作时间内首次回复，不承诺全天候）
支持范围：______（含什么、不含什么）

二、支持台账（敏感信息最小化）
日期 | 用户 | 任务/现象 | 影响 | 证据 | 状态 | 人工时间
______ | | | | | |

三、优先级（先处理影响交付的）
P0 数据访问 / 付款后不可用 / 核心流程中断
P1 结果错误但有替代路径
P2 体验或文案问题

四、复盘一次失败（没有真实故障就演练并标注）
事实时间线：__:__ 发生 → __:__ 发现 → __:__ 处理 → __:__ 恢复
原因证据：______
防复发动作：______（一条，写进帮助或产品）
帮助条目位置：______

五、本次支持时间
合计：___ 小时（用于经营核算）
```

## AI提示词包

```text
第一轮 · 起草支持说明
我的产品是 ______，我一个人维护。请写一段支持说明：入口、响应安排、支持范围、不承诺什么。
硬约束：不得承诺全天候或固定分钟内响应；不要写"随时在线"。

第二轮 · 把反馈整理成台账
这是用户反馈原文（粘贴）。请整理成台账：现象、影响、证据、状态；敏感信息最小化。
硬约束：不得编造用户或时间；缺失的字段留空并标注。

第三轮 · 拟回复（标注不能承诺的部分）
这是一条用户问题（粘贴）。请拟一段回复，并单独标出：哪些话必须由我确认后才能发（补偿、时限、责任）。
硬约束：不得擅自承诺退款、赔付或完成时间。

第四轮 · 复盘时间线
这是这次故障的记录（粘贴）。请整理事实时间线，并区分事实与推测；给一条防复发动作。
硬约束：不得把演练写成真实事故；不得编造原因。
```

## 成品样例

一份合格的成果长这样（示例数据，只用于对照格式）：

- 支持入口：邮箱 + 表单；响应安排：工作时间内首次回复，不承诺全天候
- 范围：含使用问题与导出失败；不含定制开发
- 台账：10-26 用户 U2，导出失败，影响交付，证据=截图+订单号，状态=已修复，人工 40 分钟
- 优先级：P0（付款后无法导出）
- 时间线：14:10 收到 → 14:20 复现 → 15:00 修复 → 15:10 回复
- 防复发：在导出页加"失败时保留输入"的提示，写进帮助条目
- 支持时间：本轮合计 1.5 小时，进入经营核算

同样的工作量，但这些**不能用**：

- AI 回复"已修复"但没有运行验证——用户会再次失败
- 没有真实故障却写"处理了一次客户事故"——演练必须标注
- 只记问题数量，不记人工时间——经营核算会失真

## AI边界

- 可以让 AI 做：起草支持说明、整理台账、拟回复初稿、整理时间线
- 不能让 AI 做：擅自承诺补偿或时限、编造故障原因、把演练写成真实事故
- 必须你本人判断：问题影响范围；修复是否经过运行验证；哪些话必须你亲自确认后才能发

## 行动步骤

### 提供明确支持入口

写清联系方法与自己能履行的响应安排，不承诺全天候服务。

#### 这一步留下

支持说明。

### 逐项记录问题

保存任务、现象、影响、必要证据和状态；客户敏感信息最小化保存。

#### 这一步留下

支持台账。

### 先处理影响交付的问题

数据访问、付款后无法使用、核心流程中断优先。AI 拟回复由你核对，不让它擅自承诺补偿和时间。

#### 这一步留下

问题优先级与处理记录。

### 复盘一次实际失败

没有真实故障时，用测试数据演练一次导出失败并明确标记演练；不要为完成任务编造客户事故。写事实时间线、原因证据和一项防复发动作。将常见解答放回帮助内容，仍不清楚的流程继续改产品。

#### 这一步留下

小型复盘与帮助条目。
