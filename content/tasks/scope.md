# 确定首版范围，拿到试用反馈

## 为什么做

生成原型更快后，范围取舍成为关键。先把最小价值闭环做清楚，再扩大开发。

## 开始条件

已有问题证据，能邀请一位目标用户试用。

## 学习要点

- 用户任务
- 最小范围
- 正常与失败状态

## 成果模板

```text
用户与场景：
输入→处理→输出：
首版包含：
暂不包含及原因：
正常/空/失败行为：
试用结果：
```

## 教学示例

教学示例：先做固定字段记录到一种报告，不支持随意上传所有文件。“生成预览”必须对应清楚的输出，不只是一个按钮。

## 常见问题

- 原型看起来完善却无法试用：减少装饰，做通一条任务。
- 用户只说好看：请他完成具体任务，观察过程。

## 交付成果

- 产品约定
- 主流程与状态
- 一轮真实试用记录

## 下一步

继续写接口约定与初始报价，再进入实现。

## 完成标准

- 规则和边界得到目标用户确认
- 样例能区分成功、空结果和失败
- 有真实行动反馈，不能只写“感兴趣”

## AI参与方式

使用 Cursor 或 Claude Code 辅助原型；产品取舍由你确认。

## 行动步骤

### 写一句产品约定

为哪类人在什么情境下完成什么结果；与现有做法相比具体改善哪里。先不写技术品牌。

#### 这一步留下

一句价值描述。

### 画一条主流程

为报告工具画“输入→校验→预览→导出”；每页写一个主动作、空状态和失败反馈。

#### 这一步留下

四步以内的初版主流程。

### 删去不影响验证的功能

首版只支持一个输入格式和一个输出模板。团队空间、模板商城与智能助手若无验证需要，暂不加入。

#### 这一步留下

包含/暂不包含清单。

### 做诚实原型

可以用 Cursor 或 Claude Code 辅助页面，也可纸面演示。明确假数据、尚未实现的按钮和人工步骤。

#### 这一步留下

可试用或可讲清的原型。

### 观察并修正

给任务而非点击提示；记录用户是否理解、是否完成、输出能否用于后续工作。修改最主要卡点。

#### 这一步留下

试用观察与一轮修订。

首版范围裁剪表
