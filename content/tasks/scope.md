# 确定首版范围，拿到试用反馈

## 为什么做

生成原型更快后，范围取舍成为关键。先把最小价值闭环做清楚，再扩大开发。

## 开始条件

已有问题证据，能邀请一位目标用户试用。

## 学习要点

- 用户任务
- 最小范围
- 正常与失败状态

## 成果模板

```text
用户与场景：
输入→处理→输出：
首版包含：
暂不包含及原因：
正常/空/失败行为：
试用结果：
```

## 教学示例

教学示例：先做固定字段记录到一种报告，不支持随意上传所有文件。“生成预览”必须对应清楚的输出，不只是一个按钮。

## 常见问题

- 原型看起来完善却无法试用：减少装饰，做通一条任务。
- 用户只说好看：请他完成具体任务，观察过程。

## 交付成果

- 产品约定
- 主流程与状态
- 一轮真实试用记录

## 下一步

继续写接口约定与初始报价，再进入实现。

## 完成标准

- 规则和边界得到目标用户确认
- 样例能区分成功、空结果和失败
- 有真实行动反馈，不能只写“感兴趣”

## AI参与方式

使用 Cursor 或 Claude Code 辅助原型；产品取舍由你确认。

## 行动步骤

### 写一句产品约定

为哪类人在什么情境下完成什么结果；与现有做法相比具体改善哪里。先不写技术品牌。

#### 这一步留下

一句价值描述。

### 画一条主流程

为报告工具画“输入→校验→预览→导出”；每页写一个主动作、空状态和失败反馈。

#### 这一步留下

四步以内的初版主流程。

### 删去不影响验证的功能

首版只支持一个输入格式和一个输出模板。团队空间、模板商城与智能助手若无验证需要，暂不加入。

#### 这一步留下

包含/暂不包含清单。

### 做诚实原型

可以用 Cursor 或 Claude Code 辅助页面，也可纸面演示。明确假数据、尚未实现的按钮和人工步骤。

#### 这一步留下

可试用或可讲清的原型。

### 观察并修正

给任务而非点击提示；记录用户是否理解、是否完成、输出能否用于后续工作。修改最主要卡点。

#### 这一步留下

试用观察与一轮修订。


## 可运行起点

```text
一、把想法拆成动作（10 分钟）
写出用户为了拿到结果必须做的每一个动作，一行一个：
1. ______
2. ______
3. ______
→ 圈出"缺了它，用户就拿不到任何结果"的那一条。其余全部进入"以后再说"。

二、范围裁剪表（复制填写）
主流程（只能有一条）：用户 ______ → 系统 ______ → 用户拿到 ______

这条流程之外的功能：
- ______（首版不做。理由：______）
- ______（首版不做。理由：______）

默认不做的三件事（除非你能说出为什么必须做）：
1. 登录 / 账号体系 —— 只有要存用户数据时才需要
2. 设置页 / 偏好项 —— 先写死默认值
3. 多端适配 —— 先只做手机，或只做桌面

三、可点原型的最低要求（不要先做完整 UI）
- 一条能从头走到尾的路径，其余页面写"还没做"
- 用真实文案，不要"这里是标题"
- 留一个会失败的分支（输入为空、内容超长），看用户怎么办
工具任选其一：纸笔拍照、Figma，或让 AI 生成一个静态 HTML（提示词见下）

四、试用记录表（每人一张）
试用者 / 日期：
我说了什么（越少越好）：
第一次停顿发生在哪个位置：
他自己摸索了多久才继续：
最后有没有拿到结果：
他做完之后说了什么（原话）：
我据此改了什么：
```

## AI提示词包

```text
第一轮 · 把功能清单裁到一条主流程
下面是我想做的功能清单。请帮我裁剪，规则：
1. 找出"缺了它用户就拿不到任何结果"的唯一一条路径，写成：用户 ___ → 系统 ___ → 用户拿到 ___。
2. 其余每项给出一句"为什么首版不做"，不许写"以后再加"这种空话。
3. 指出哪几项其实是同一件事的不同叫法。
不要新增功能，不要优化措辞，不要给技术方案。
清单：
---
（粘贴你的功能清单）
---

第二轮 · 生成一个能点的静态原型
用单个 HTML 文件做一个可点击原型。要求：
- 只实现这一条路径：______
- 用真实文案，占位文字一律写"待定"
- 包含"输入为空"和"内容超长"两个失败分支，页面内给出提示
- 不引入任何外部依赖、不写后端、不做登录
输出完整代码，可直接保存为 index.html 打开。

第三轮 · 把试用过程整理成问题清单
下面是三段试用记录。请按「用户在哪一步停住 / 我提示了什么 / 属于产品问题还是我没说清」三列整理，
并标出至少一处"其实是我讲解过度导致的"。不要给改版建议。
---
（粘贴三段记录）
---
```

## 成品样例

合格（教学模拟，只对照格式）：

- 主流程（一条）：运营上传两个 CSV → 系统对齐字段名 → 下载一份合并表
- 明确不做：账号体系、定时任务、图表看板、多店铺管理
- 原型：1 个上传页 + 1 个结果页；空文件和超大文件都有提示
- 3 人试用：2 人自己走完，1 人在"字段名对不上"处停住
- 记下的原话：｜"这里我以为要我自己选字段"｜→ 改成自动匹配，并给出可手改的映射表

不合格：

- 写"做一个报表平台"——这不是一条流程，无法验证
- 原型有 8 个页面，其中 6 个是设置页
- 试用记录只有"反馈良好"——没有停顿位置、没有原话

## AI边界

- 可以让 AI 做：生成静态原型代码、把功能清单归类、把试用记录整理成问题清单
- 不能让 AI 做：替你决定砍掉什么（砍的依据是"缺了它还有没有结果"，只有你知道）、替你判断试用者的停顿是不是产品问题
- 必须你本人判断：主流程是不是只有一条；试用者有没有在不靠你提示的情况下走完
