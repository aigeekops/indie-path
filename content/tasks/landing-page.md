# 做一页能解释价值的落地页

## 为什么做

落地页首先是沟通与验证工具。新增模块未必提高可信度；用户要看懂结果、适用边界和下一步成本。

## 开始条件

有定位句和可展示的真实或明确标注的模拟样例。可用本地页面或现有站点，不要求购买域名。

## 学习要点

- 信息优先级
- 结果样例与证据
- 单一行动与漏斗口径

## 可运行起点

```text
一、先定一个行动（只选一个）
预约演示 / 试用 / 获取样例（三选一）
主要行动：______
成功事件：______（例：提交后看到样例页）
还不能交付时如实写：______

二、四段内容（按顺序）
1) 适合谁 + 结果
2) 结果样例（真实截图或明确标注的模拟）
3) 使用方式与限制
4) 行动入口（含需要提交什么、用来做什么）

三、最小页面（index.html，照抄后替换 ______）
<!doctype html>
<html lang="zh-CN">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>______</title>
  <link rel="stylesheet" href="style.css">
</head>
<body>
  <main>
    <h1>把两个后台的数据，整理成一份能直接发出的复盘</h1>
    <p class="sub">给每周要交投放复盘的增长运营。上传两份导出文件，得到一份可编辑的周报；由你检查后导出，不自动发送。</p>
    <p class="cta"><a class="button" href="#sample">先看一份样例（无需注册）</a></p>

    <section id="sample">
      <h2>结果样例</h2>
      <p class="note">以下为模拟数据，用于展示格式。</p>
      <img src="sample.png" alt="周报样例：渠道、花费、转化三列">
    </section>

    <section>
      <h2>怎么用、有什么限制</h2>
      <ol>
        <li>导出两个后台的 CSV</li>
        <li>上传，等待对齐</li>
        <li>检查后导出为文本或 PDF</li>
      </ol>
      <p>限制：只支持这两种后台；字段名改版时可能对不齐；不自动发送。</p>
    </section>

    <section>
      <h2>获取试用</h2>
      <form id="form">
        <label for="email">邮箱（只用于发送试用链接）</label>
        <input id="email" type="email" required>
        <button type="submit">申请试用</button>
      </form>
      <p id="status" role="status"></p>
      <p class="note">表单尚未接通后端时，提交后只显示"演示版：未保存"，不得显示"报名成功"。</p>
    </section>
  </main>
  <script src="app.js"></script>
</body>
</html>

【app.js】（未接通后端时的诚实占位）
document.querySelector('#form').addEventListener('submit', (e) => {
  e.preventDefault();  // 不真正提交
  document.querySelector('#status').textContent = '演示版：表单未接通，未保存任何信息。';
});

（sample.png 换成你的真实截图；没有截图就先用一个写着"模拟样例"的色块。）

四、移动端走一遍
窄屏（375px）检查：标题是否被截断、按钮是否可点、表单校验是否提示、提交后是否有明确反馈。

五、观察理解
请目标用户复述："这是给谁用的？做什么？你会不会点？"
记录：不理解 / 不需要 / 入口故障（三选一）
```

## AI提示词包

```text
第一轮 · 只组织四段内容
这是我的定位句（粘贴）。请按"适合谁+结果 / 结果样例 / 使用方式与限制 / 行动入口"四段组织文案。
硬约束：不得添加客户评价、不得编造数据；没有证据的承诺标"待验证"。

第二轮 · 生成最小页面
把上面四段做成一个单页 HTML（含一个主要行动）。窄屏优先，不引入框架。
硬约束：只留一个主要按钮；模拟样例必须显著标注；表单未接通时不得显示"成功"。

第三轮 · 检查承诺与证据
这是我的页面文案（粘贴）。请逐句标出：有证据 / 无证据 / 无法兑现，并给出删除建议。
硬约束：只删不增；不得替我写"提升 300%"这类数字。

第四轮 · 分析复述与行动障碍
用户看完后说（粘贴）。请区分：不理解（没看懂用途）、不需要（看懂了但不适用）、入口故障（想点但点不到）。
硬约束：不得把"没提交"直接判为"不需要"。
```

## 成品样例

一份合格的成果长这样（示例数据，只用于对照格式）：

- 主要行动：看一份样例（无需注册）；成功事件：打开 sample 页
- 首屏一句话："把两个后台的数据，整理成一份能直接发出的复盘"
- 结果样例：`sample.png`，显著标注"模拟数据"
- 证据/限制：10-20 录屏证明手动改 20 行；限制写"只支持这两种后台、不自动发送"
- 信息收集：邮箱只用于发试用链接
- 移动端：375px 下标题两行、按钮 44px 高、邮箱校验提示"请输入邮箱"、提交后显示"已记录，稍后联系"
- 用户理解：3 人中 1 人以为"会自动发给客户" → 在入口旁加"由你检查后导出"
- 本次修改：入口文案；下一次观察：是否有人真的打开 sample

同样的工作量，但这些**不能用**：

- 首屏写"AI 驱动的智能数据平台"——看不出给谁、做什么
- 放虚构客户评价或"提升 300%"——没有证据
- 表单没接通却显示"报名成功"——用户以为有效，实际没记录

## AI边界

- 可以让 AI 做：按四段组织文案、生成单页 HTML、逐句检查承诺与证据、归类复述障碍
- 不能让 AI 做：编造客户评价或效果数字、把未接通表单写成"成功"、替你判断"这个页面的价值说清楚了没有"
- 必须你本人判断：首屏是否说清对象与结果；模拟样例有没有显著标注；移动端行动是否真的走得通

## 行动步骤

### 确定页面只服务一个行动

选预约演示、试用或获取样例之一，说明对象与需要提交的信息；还不能交付就如实说明。

#### 这一步留下

主要行动及成功事件。

### 组织四段内容

依次写适合谁与结果、结果样例、使用方式与限制、行动入口。价格未知就说明如何获取报价。

#### 这一步留下

页面内容草图。

### 检查承诺和证据

截图隐去隐私，模拟示例显著标注；没有客户评价就不放虚构评价。把维护者、反馈方式写清。

#### 这一步留下

可发布的内容与证据。

### 走完移动端行动

用窄屏检查可读性、按钮、表单校验与成功提示。暂未接收数据的表单不能显示报名成功。

#### 这一步留下

一次完整行动记录。

### 观察理解与下一步

请目标用户复述用途并试一次行动，区分不理解、不需要和入口故障，选择一处修改。

#### 这一步留下

反馈与修订记录。

## 教学示例

教学模拟，以下数字与情境不是市场调查结果。

模拟页面只保留“看一份周报样例”。观察发现访客以为必须注册，便把“无需注册，查看可编辑结果示例”写在入口旁。没有后续数据时不能声称转化提升。

## 常见问题

- 多个同等醒目的按钮：确定一个当前目标。
- 填完表单就算有效用户：继续观察真实使用。

## 交付成果

- 可打开的落地页
- 理解与行动检查记录

## 完成标准

- 对象、结果、边界可找到
- 主行动有真实可达的结果
- 移动端操作记录无未解释阻塞

## AI参与方式

让 AI 起草页面结构和实现，自己核查事实、隐私与实际表单行为。
