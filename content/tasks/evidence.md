# 检查你已有的需求证据

## 为什么做

做过产品或运营，不等于当前项目已经验证。复用已有材料，避免把职业经验当成此次需求证据。

## 开始条件

已有访谈、手工服务或试用记录。

## 学习要点

- 证据分级
- 反例与人群差异
- 最重要的未知

## 成果模板

```text
假设/适用人群：
材料目录（日期/来源位置）：
记录 | 观察事实/用户表述/行为承诺/我的推断 | 原始出处
支持它的原始事实：
反例/适用边界：
尚未确认：
最小验证动作/回访对象/约定时间：
下一步承诺或暂停理由：
本轮决定：
```

## 教学示例

教学示例：三人称赞模板，一人愿意提供脱敏记录。不能写成“四位潜在客户”；先与提供记录的人确认报告是否实际可交付。

## 常见问题

- 记录只有总结：回到原始材料，缺失就如实标注。
- 拿过去另一款产品的成功当证据：重新检查人群、场景和付费对象。

## 交付成果

- 证据与反例表
- 下一轮最小验证动作

## 下一步

进入范围与报价任务；服务用户可先拆自助环节。

## 完成标准

- 每条关键结论能回到原始记录
- 有具体下一步承诺，或明确证据不足

## AI参与方式

辅助分类和找反例，不替代用户确认。

## 可运行起点

```text
一、收齐材料（保留日期与来源）
材料 1：______（日期/位置）
材料 2：______
材料 3：______
自己写的需求清单单独放，不算用户证据。

二、逐条分类（四种只能选一种）
观察事实：你亲眼看到他做了什么（例：他把两个 CSV 粘进 Excel）
用户表述：他说的原话（例："字段对不上我就手动改"）
行为承诺：他答应做的下一步（例："周三给你一份脱敏记录"）
我的推断：你从上面三条推出来的（例："他每周至少花 2 小时"）

记录 | 原文/事实 | 类别 | 出处
1 | | |
2 | | |
3 | | |

三、查一条反例（必须真的找）
对象：______
他没遇到这个问题的原因：______
是不是不同人群：______

四、补最关键的一次确认（只挑一个）
影响"要不要开发"的那个缺口：______
回访对象/时间：______
得到的承诺或结论：______

五、本轮决定
继续 / 缩小范围 / 暂停，理由：______
```

## AI提示词包

```text
第一轮 · 只分类，不评价
下面是我的记录（粘贴）。请逐条标为：观察事实 / 用户表述 / 行为承诺 / 我的推断。
硬约束：不得把推断写成事实；拿不准的标"待确认"，不要猜。

第二轮 · 找反例
基于这些记录，列出三类可能推翻结论的人：没遇到问题的、已有满意方案的、不愿改变的。
硬约束：只给"该去找谁"的画像，不要编造他们的说法。

第三轮 · 找最关键缺口
这些记录支持"继续做"吗？请指出：如果有一个未知为假，会让整个项目失去意义，那是什么？
硬约束：只给一个未知，并说明为什么它最关键。

第四轮 · 设计一次确认
针对这个未知，设计一次 10 分钟回访：问什么、要拿到什么承诺算数。
硬约束：不得设计"你会不会用"这类假设性问题；承诺必须是具体行为。
```

## 成品样例

一份合格的成果长这样（示例数据，只用于对照格式）：

- 材料目录：10-20 访谈录音（微信语音）/ 10-21 脱敏记录.xlsx / 10-22 试用反馈截图
- 记录 1："数据要从小红书后台和生意参谋分别导" → 用户表述 → 10-20 录音 03:12
- 记录 2：他现场把两个 CSV 粘进 Excel 用 VLOOKUP → 观察事实 → 10-20 录屏
- 记录 3：答应周三给一份脱敏记录 → 行为承诺 → 10-20 录音 12:40
- 记录 4："他每周至少花 2 小时" → 我的推断 → 由记录 1+2 推出
- 反例：另一位运营说"我们系统自动出报表" → 属于不同人群（有 BI 支持）
- 最关键缺口：他是否愿意为"自动对齐字段"付费
- 回访结果：愿意先试用，不愿先付；承诺下周三给一次真实数据
- 本轮决定：继续，但把"付费"标为未验证

同样的工作量，但这些**不能用**：

- 把"三人称赞"写成"四位潜在客户"——称赞不是行为
- 拿上一款产品的成功当这次的证据——人群、场景、付款人都变了
- 只有总结没有原话/出处——后面无法核对

## AI边界

- 可以让 AI 做：按四类给记录分类、列反例画像、指出最关键未知、设计回访问题
- 不能让 AI 做：编造用户原话或承诺、把推断升级成事实、替你判断"证据够不够"
- 必须你本人判断：每条结论能否回到原始记录；反例是不是不同人群；承诺是否具体到可执行

## 行动步骤

### 收齐原始材料

整理访谈、样例、试用和服务记录，保留日期和来源。作者自己写的需求清单单独放。

#### 这一步留下

带来源的材料目录。

### 区分四种信息

逐条标为观察事实、用户表述、行为承诺或你的推断。用户愿意约下一次演示比单纯称赞更具体，仍不等于付款。

#### 这一步留下

证据分类表。

### 查一条反例

找未遇到问题、已有满意方案或不愿改变的人。记录原因，确认是不是不同人群。

#### 这一步留下

一条反例与适用边界。

### 补最关键的一次确认

只挑影响是否开发的一个缺口，回访确认。没有可靠依据就缩小范围或暂停。

#### 这一步留下

一项明确的下一步承诺，或暂停理由。
