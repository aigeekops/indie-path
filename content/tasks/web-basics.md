# 看懂页面、请求与服务端

## 为什么做

AI 降低了写页面的门槛，但你需要看懂浏览器、请求与服务端，才能知道哪里失败。

## 开始条件

没有独立前后端经验；会写代码者可先对照验收尝试。

## 学习要点

- HTML/CSS基础
- 请求响应
- 静态页面与服务端的区别

## 成果模板

```text
页面元素→对应文件：
请求URL/方法/响应：
浏览器保存什么：
服务端保存什么：
失败发生在哪一步：
```

## 教学示例

教学示例：本指南通过静态文件与本地存储保存进度，刷新后仍在不等于有云端账户；换浏览器不会自动同步。

## 常见问题

- 网页打不开：先查文件、资源路径和控制台。
- 以为 HTML 内的密钥能隐藏：任何发到浏览器的内容都可被查看。

## 交付成果

- 最小页面
- 请求说明
- 系统图

## 下一步

继续编程与调试基础，再写接口与界面。

## 完成标准

- 能修改并解释页面的三个元素
- 能指出一条请求与响应
- 区分浏览器、本地存储与服务端

## AI参与方式

使用 Cursor 或 Claude Code 辅助整理与局部实现，自己核对关键事实和结果。

## 行动步骤

### 做一个最小页面

按 MDN 示例创建标题、说明、输入框和按钮，连接一份样式表。能打开并定位每个元素即可。

#### 这一步留下

一页自己的产品说明。

### 改三处看得见的内容

调整文字、宽度和间距，再恢复一处变化。使用编辑器差异核对改动，不用重做整站。

#### 这一步留下

可解释的三项修改。

### 观察一条请求

在课程示例的 Network 中找 URL、方法、状态和响应。画出浏览器发请求、服务器返回数据的过程。

#### 这一步留下

一张请求说明。

### 区分存在哪里

说明页面代码、浏览器本地记录和服务端数据各在哪里。写明为何静态托管不能运行自己的服务端程序或藏密钥。

#### 这一步留下

最小系统图。
