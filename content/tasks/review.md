# 回访实际用户，查清未付费原因

## 为什么做

上线不等于价值成立。AI 可以归纳反馈，却不能从没有付款直接推断“功能不够”。先分开需求、使用、购买和交付。

## 开始条件

已有试用记录；付费用户也可以回访持续价值。

## 学习要点

- 使用漏斗
- 购买决策
- 拒绝原因调查

## 成果模板

```text
用户/日期/原始记录位置：
访问/开始/完成/付款（各写实际行为或未知）：
是否完成核心任务：
结果用于哪里/仍需人工的地方：
报价/计费单位/额度/支持范围/付款人：
接受/拒绝/延期/未回应（原话）：
未继续的原话：
待验证原因（推断单列）：
下一轮只改什么/核对节点：
```

## 教学示例

教学示例：五人试用、两人导出，不代表两人获得价值；其中一人实际用于客户交付、另一人只是测试。优先回访真实任务与购买障碍。

## 常见问题

- 无回复：只能记录未取得反馈，不能判定价格太贵。
- 用户提新功能：追问对应任务与是否影响购买，再决定。

## 交付成果

- 行为分组
- 原话与报价反馈
- 一项优先假设

## 下一步

已有产品用成果确认实现任务；优先解决使用或交易瓶颈。

## 完成标准

- 区分试用、核心任务完成与实际付费
- 记录用户原话，未付款如实保留

## AI参与方式

辅助整理反馈，不自动断言“缺功能”。

## 可运行起点

```text
一、按实际行为分组（不按感觉）
用户 | 访问 | 开始 | 完成 | 付款 | 记录完整性
U1 | | | | |
U2 | | | | |
没有事件数据 → 逐个回访，标"记录不完整"。

二、回访最近一次使用（先听，不先演示）
"最近一次用是什么时候？结果真的用在工作里了吗？"
"哪里还需要你手动补？"
"后来为什么没有继续？"
原话记录（至少 3 句）：
______

三、提出真实报价（未付费者）
交付：______ 计费单位：______ 额度：______ 支持范围：______ 付款人：______
回应：接受 / 拒绝 / 延期 / 未回（原话）：______

已付费者改为核对：
订单与实际交付是否一致：是 / 否
下次自然使用时间：______
支持耗时：______

四、只改一个关键因素
没人完成 → 先改流程
完成但不购买 → 查价值 / 付款人 / 价格 / 信任（只选一个）
下一轮验证：______ 核对节点：______
```

## AI提示词包

```text
第一轮 · 按行为分组
这是我的用户记录（粘贴）。请按"只访问 / 开始 / 完成 / 付款"分组，并标出记录不完整的人。
硬约束：不要推断动机；没有数据的格子留"未知"，不要补。

第二轮 · 整理原话（推断单列）
这是回访记录（粘贴）。请把用户原话与我的推断分开，推断必须标明依据。
硬约束：不得把"我觉得他嫌贵"写成用户原话。

第三轮 · 检查报价要素
这是我的报价（粘贴）。请检查：交付、计费单位、额度、支持范围、付款人是否齐全。
硬约束：不要替我定价格；缺哪项就指出哪项。

第四轮 · 只选一个关键因素
这是行为分组与报价反馈（粘贴）。请判断应先改流程、价值、付款人、价格还是信任，只给一个，并说明依据。
硬约束：不得同时建议改多个因素；不得断言"缺功能"。
```

## 成品样例

一份合格的成果长这样（示例数据，只用于对照格式）：

- 分组：5 人试用 / 2 人导出 / 1 人真正用于客户交付 / 0 人付款
- 回访原话："导出的格式还要再调"｜"老板没要求，我就没继续"｜"再看看"
- 报价：一份报告 20 元 / 按次 / 含一次修改 / 支持 3 天；付款人是用户本人
- 回应：1 人拒绝（"公司有模板"），1 人延期，3 人未回
- 判断：不是价格问题，是"没有持续使用场景"
- 下一轮只改：价值表达（不是加功能），核对节点 11-02

已付费者（变体情形）改为：

- 订单与实际交付一致；下次自然使用时间 11-05；支持耗时 40 分钟
- 尚未到观察周期 → 标"待观察"，不认定续用

同样的工作量，但这些**不能用**：

- 把"2 人导出"写成"2 人获得价值"——只有 1 人真正用于交付
- 没人回复就判定"价格太贵"——那只是未取得反馈
- 用户提"加个功能"就直接排期——先追问对应任务与是否影响购买

## AI边界

- 可以让 AI 做：按行为分组、整理原话与推断、检查报价要素、在多个因素里选一个
- 不能让 AI 做：断言"缺功能"、编造用户回应、把未回应当作拒绝原因
- 必须你本人判断：谁真正完成了核心任务；结果有没有被实际使用；未付款的真实原因

## 行动步骤

### 按实际行为分组

找出只访问、开始任务、完成任务、已经付款的人。没有事件数据时逐个回访，标记记录不完整。

#### 这一步留下

按用户与时间整理的实际行为。

### 回顾最近一次使用

问结果是否真的用于工作、哪里仍需人工、为什么没有继续。先听经历，再演示改进。

#### 这一步留下

价值与失败情境。

### 提出真实报价

写出交付、计费单位、额度和支持范围，请对方明确下一步；已付费者核对交付与再次使用。

#### 这一步留下

购买、拒绝或延期记录。

### 只改变一个关键因素

如果没人完成先改流程；完成但不购买先检查价值、付费人、价格与信任。不要同时改人群、功能和价格。

#### 这一步留下

下一轮验证计划。
