# 接入 AI 并算清每次有效使用的成本

## 为什么做

一次请求便宜，不代表完成一次用户任务便宜。重试、长输入和不可用输出都可能让成本超过收费。

## 开始条件

已有服务端接口和一个有限的 AI 任务。资料免费，真实 API 通常按量计费；先写预算上限，也可用明确标注的模拟响应练习结构。

## 学习要点

- 服务端凭证与用量记录
- 任务级成本
- 成本上限与结果质量

## 可运行起点

```text
一、先写死任务契约（一次任务的边界）
输入上限：___ 字 / ___ 条记录
输出结构：______（例：固定三段：问题、建议、引用）
失败条件：______（超时 / 非 JSON / 缺字段 / 拒答）
供应商与模型：______（读当期价格页，记下日期）

二、密钥只放服务端（Node 示例）
// server.mjs
const KEY = process.env.AI_API_KEY;   // 不进前端、不进仓库
export async function runTask(input) {
  const started = Date.now();
  const res = await fetch(process.env.AI_BASE_URL + '/chat/completions', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json', Authorization: `Bearer ${KEY}` },
    body: JSON.stringify({
      model: process.env.AI_MODEL,
      messages: [{ role: 'user', content: input }],
      max_tokens: 800
    })
  });
  const data = await res.json();
  return { ok: res.ok, status: res.status, usage: data.usage, ms: Date.now() - started, data };
}

三、成本表（按实际计费单位填，不估算）
样例数 | 通过数 | 输入用量 | 输出用量 | 失败/重试 | 总可变成本 | 每个有效结果成本
______ | ______ | ______ | ______ | ______ | ______ | ______

公式：每个有效结果成本 = 本批总可变成本 ÷ 验收通过任务数
分母为 0 → 写"不可计算"，不要写 0。

四、预算边界（必须能触发一次）

触发记录：______（时间、用户、当时的用量）

五、质量对照（同一组样例）
版本 A：通过 ___ / 成本 ___ / 耗时 ___
```

## AI提示词包

```text
第一轮 · 只写适配层
这是我的任务契约（粘贴）。请只写调用适配层：从环境变量读密钥与模型名，带超时和重试上限。
硬约束：不得把密钥写进前端或仓库；不得改动业务逻辑；不得替我想象价格。

第二轮 · 设计成本表字段
按"输入用量 / 输出用量 / 其他费用 / 失败与重试 / 通过数"设计表格字段，并说明每项从哪里取数。
硬约束：不要把估算写成实测；模拟数据必须标注。

第三轮 · 检查静默扣费路径
这是我的调用与重试逻辑（粘贴）。请列出所有可能静默扣费的路径（无限重试、超长输入、循环调用、配额未生效）。
硬约束：只列路径与最小修法，不重写整个模块。

第四轮 · 做质量-成本对照
这是两个版本在同一组样例上的结果（粘贴）。请比较通过数、严重错误、耗时与总成本。
硬约束：不得只推荐最便宜的版本；严重错误单列，不用平均分掩盖。
```

## 成品样例

一份合格的成果长这样（示例数据，只用于对照格式）：

- 任务：把一段记录整理成三段式摘要；输入上限 2000 字；输出固定三段
- 供应商/模型/价格日期：某供应商某模型 / 10-26（以当期页面为准）
- 测试类型：模拟响应（不是真实账单）
- 批次：20 次任务产生 24 次调用，15 个结果通过
- 用量：输入 ___ tokens / 输出 ___ tokens / 其他 ___
- 失败与重试：4 次失败、4 次重试；总可变成本（模拟）1.20 元
- 每个有效结果成本：1.20 ÷ 15 = 0.08 元
- 预算边界：单任务 800 tokens、最多 2 次重试；超额停止并提示
- 触发记录：10-26 15:40 用户 U3 触发单任务上限，返回"请缩短输入"
- 质量对照：A 版 9/15 通过、0.06 元；B 版 12/15 通过、0.08 元 → 选 B，但严重错误另计

同样的工作量，但这些**不能用**：

- 用 1.20 ÷ 24 = 0.05 当有效结果成本——把失败和重试摊薄了
- 只记录成功请求——失败、重试、超时都不进成本
- 模拟跑通就写"已接通真实 API"——模拟与真实账单必须分开

## AI边界

- 可以让 AI 做：写调用适配层、设计成本表字段、列静默扣费路径、整理质量-成本对照
- 不能让 AI 做：替你确认账单金额、编造价格或用量、替你判断"这个质量可以发布"
- 必须你本人判断：密钥是否只在服务端；失败与重试是否进了成本；价格出处与日期是否真实

## 行动步骤

### 写清输入输出与调用边界

定义一次任务的输入上限、输出结构和失败条件；只选实际可用的供应商，阅读其当期调用与数据处理说明。

#### 这一步留下

任务契约与供应商选择依据。

### 在服务端完成最小调用

密钥留在服务端，校验用户身份和输入；记录请求标识、模型版本、用量、耗时与错误，日志不保存密钥或未经许可的用户原文。

#### 这一步留下

成功与失败的脱敏调用记录。

### 计算有效结果成本

按实际计费单位核对输入、输出和其他费用，汇总失败与重试。有效结果成本=本批总可变成本/验收通过任务数；分母为零则不可计算。

#### 这一步留下

任务级成本表及价格核对日期。

### 设置可执行的预算边界

限制单任务输入、输出、重试次数与用户配额；预算不足时明确停止并提示，不能无限重试或继续静默扣费。

#### 这一步留下

限制配置和触发记录。

### 结合质量做取舍

用同一小组样例比较改动前后通过数、耗时与总成本，不能只选最便宜模型。模拟记录与真实账单分别标注。

#### 这一步留下

一次成本与质量的对照决定。

## 教学示例

教学模拟，以下数字与情境不是市场调查结果。

假设一批20次任务产生24次调用，总可变成本为模拟的1.20元，只有15个结果通过验收，则有效结果成本为0.08元。只算1.20/24会低估每次成功交付的成本；这些数字不是任何供应商报价。

## 常见问题

- 把密钥放前端：改由服务端受控调用。
- 只记录成功请求：失败与重试也要进入成本。
- 模拟通过后写已接通：分别记录模拟和真实验证。

## 交付成果

- 可解释的最小接入记录
- 成本表与预算限制验证

## 完成标准

- 凭证不暴露给浏览器
- 成本含失败和重试并注明价格日期
- 至少验证一次超额停止行为
- 模拟与真实结果明确区分

## AI参与方式

让 AI 辅助实现适配与成本公式，自己核查调用、账单和输出质量。
